# Bring-up and acceptance gates

1. **Capture the working tablet.** Record MZ604 identity, ROM provenance, kernel config, boot image layout, cmdline, partition map, recovery version and BigPart state. Save restorable backups externally.
2. **Reproduce 2.6.39.4.** Fetch pinned sources, start with the pinned kernel’s `stingray_defconfig`, select a compatible historical ARM compiler and build. The Marshmallow device tree requests `elementalxvanilla_defconfig`, which is absent from the pinned `jb-mr2` kernel; resolve the intended ElementalX kernel revision before claiming to reproduce the Marshmallow ROM. The supplied script builds the older kernel baseline and is a starting point, not a verified historical build environment. Capture toolchain checksum and build logs. Repack using the measured working boot image parameters and test recovery access before baseline boot testing.
3. **Audit Oreo dependencies.** Resolve all local-only projects in Decatf's manifest, inspect surviving branches/forks and license provenance, and produce a fully pinned public-source manifest. Recover Wingray vendor dependencies separately. Do not commit device dumps or proprietary blobs by default.
4. **Port the 4.4 board.** Compare Xoom board initialization with donor Tegra support. Choose device tree versus legacy board code based on the donor. Bring up early logging, memory, interrupts, clocks, regulators, storage and BigPart mapping first. Keep an independent recovery image.
5. **Boot a minimal ramdisk.** Require reliable console/log capture, correct partition visibility, read-only mount tests and stable reboot before starting Android.
6. **Restore hardware.** Display, touch and USB/ADB, then Wi-Fi, audio, charging and suspend/resume. Record each as untested, broken or working. Compare legacy GPU ABI with donor graphics path before selecting Android HALs.
7. **Android integration.** Start with minimal no-GApps non-NEON builds; use 7.1.2 as a diagnostic milestone if necessary, then 8.1. Validate binder/ashmem, SELinux policy, init, graphics allocation/composition and media. Do not blindly carry the old SELinux-disabled cmdline into a finished ROM.
8. **Acceptance.** Repeated cold boots; usable UI and ADB; correct storage geometry; Wi-Fi reconnect; audio; battery/charging; screen off/on; suspend/resume; stress without OOM loops; measured RAM and performance; reliable recovery and rollback. Camera/video/GPS/Bluetooth status must be stated explicitly.

Current status: the initial Wingray Linux 4.4.147 source changes cross-compile to zImage and appended DTB. See `kernel/README.md` for implemented paths, verification and unfinished drivers. There is no flashable boot image, hardware boot result or working Oreo port yet.
